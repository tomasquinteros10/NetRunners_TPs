      \item
        Las redes se clasifican seg\'un su alcance de la siguiente manera:
        \begin{itemize}
          \item \textbf{PAN (Personal Area Network):} cubre solo unos metros y sirve para conectar los dispositivos cercanos de una sola persona. Por lo general, usa tecnolog\'ias como Bluetooth y USB.
          \item \textbf{LAN (Local Area Network):} son redes limitadas a un espacio f\'isico peque\~no, como una casa, una oficina o un edificio. Buscan ofrecer una alta velocidad y baja latencia.
          \item \textbf{CAN (Campus Area Network):} de tama\~no intermedio, busca conectar varias LAN de edificios cercanos, como un campus universitario o un conjunto de edificios cercanos de una empresa. Suele ser propiedad de un solo ente, que es el mismo que la utiliza.
          \item \textbf{MAN (Metropolitan Area Network):} cubre un pueblo o una ciudad entera. Conecta m\'ultiples redes LAN a trav\'es de conexiones de alta velocidad, como fibra \'optica. Su infraestructura est\'a desarrollada, por lo general, por empresas que luego cobran por su acceso a la red.
          \item \textbf{WAN (Wide Area Network):} tiene un alcance muy amplio: abarca pa\'ises, continentes o el mundo entero. Internet es el ejemplo m\'as grande de una WAN. Interconecta redes m\'as peque\~nas entre ellas utilizando l\'ineas telef\'onicas, sat\'elites o cables submarinos.
        \end{itemize}
      \item
        Una VLAN es una tecnolog\'ia mediante la cual se pueden separar l\'ogicamente dos o m\'as redes que se encuentran conectadas a un mismo conmutador f\'isico para que funcionen como redes independientes.

        Se clasifican en:
        \begin{itemize}
          \item \textbf{VLAN nivel 1:} se especifica qu\'e puerto del switch pertenece a cada VLAN; el usuario que se conecte a ese puerto pertenecer\'a a esa VLAN. Esto genera que el usuario pierda movilidad, ya que si se conecta a otro puerto en otro lugar de la red puede pasar a pertenecer a una VLAN diferente.
          \item \textbf{VLAN nivel 2:} se asocian mediante la MAC del dispositivo que se conecta. Esto permite la movilidad de los usuarios, aunque vuelve la configuraci\'on inicial un reto si existen m\'ultiples dispositivos.
          \item \textbf{VLAN nivel 3:} se segmentan las redes por el protocolo especificado en la trama MAC. Existir\'a una VLAN para protocolo IPv4, IPv6, etc.
          \item \textbf{VLAN nivel 4:} en este nivel, el switch se basa en la cabecera de nivel 3 para identificar a qu\'e subred pertenece la direcci\'on de origen del paquete. En este nivel no se define qu\'e estaci\'on pertenece a qu\'e VLAN, sino qu\'e paquete pertenece a qu\'e VLAN. Por lo que una misma estaci\'on enviar\'a paquetes a diferentes VLAN seg\'un qu\'e datos lleve la cabecera.
          \item \textbf{VLAN de niveles superiores:} se clasifican por uso de aplicaci\'on. Por ejemplo, FTP, email, etc. Adem\'as, la pertenencia a una VLAN puede basarse en varios factores, como puertos, horas del d\'ia, subredes, formas de acceso, etc.
        \end{itemize}
      \item
        Es un protocolo que se ide\'o para generar un mecanismo que permita a m\'ultiples redes compartir un mismo medio f\'isico. Se usa para definir el encapsulamiento usado para implementar este mecanismo en redes Ethernet. El protocolo consiste en modificar la trama de Ethernet para agregar cuatro bytes y modificar el campo EtherType para identificar que se modific\'o la trama. Estos cambios obligan tambi\'en a recalcular el campo FCS.

        Cada dispositivo de interconexi\'on que desee soportar VLAN debe implementar este protocolo.
      \item
        Es la forma que define el protocolo para diferenciar tramas de distintas VLAN. Se agregan cuatro bytes a la trama Ethernet: los dos primeros bytes redefinen el EtherType a 0x8100, pero no se sobreescribe el original, ya que queda inmediatamente a continuaci\'on de estos cuatro bytes. Los otros dos bytes (16 bits) que se insertan en el proceso de tagging incluyen:
        \begin{itemize}
          \item \textbf{PCP (Priority Code Point, 3 bits):} sirve para definir la prioridad de la trama.
          \item \textbf{DEI (Drop Eligible Indicator, 1 bit):} si se encuentra en 1, da indicativo a una red saturada de que la trama es elegible para ser descartada y evitar la saturaci\'on.
          \item \textbf{VID (VLAN Identifier, 12 bits):} permite identificar la red VLAN a la que pertenece la trama.
        \end{itemize}
    \end{enumerate}

      \textbf{DHCP y configuración de pools} \\[0.5em]
        Se configuró el Router1 como servidor DHCP de las tres VLANs, con un \textit{pool} por cada una. Cada pedido de un PC llega al router a través de la subinterfaz correspondiente, que le contesta con una IP disponible de esa red. Cada \textit{pool} define la red a repartir (\texttt{network}), el \textit{gateway} a informar (\texttt{default-router}) y un servidor DNS (\texttt{dns-server}, se usó \texttt{8.8.8.8} como ejemplo genérico). Además, se excluyeron las primeras diez direcciones de cada subred para reservarlas a asignaciones manuales, como el servidor.

        \begin{lstlisting}
        Router1(config)# ip dhcp excluded-address 10.10.10.1 10.10.10.10
        Router1(config)# ip dhcp excluded-address 10.10.20.1 10.10.20.10
        Router1(config)# ip dhcp excluded-address 10.10.99.1 10.10.99.10
        Router1(config)# ip dhcp pool TURISTA
        Router1(dhcp-config)# network 10.10.10.0 255.255.255.0
        Router1(dhcp-config)# default-router 10.10.10.1
        Router1(dhcp-config)# dns-server 8.8.8.8
        Router1(dhcp-config)# exit
        Router1(config)# ip dhcp pool BUSINESS
        Router1(dhcp-config)# network 10.10.20.0 255.255.255.0
        Router1(dhcp-config)# default-router 10.10.20.1
        Router1(dhcp-config)# dns-server 8.8.8.8
        Router1(dhcp-config)# exit
        Router1(config)# ip dhcp pool ADMIN

      \textbf{NAT e Internet} \\[0.5em]
        Dado que Packet Tracer no dispone de salida real a Internet, se simuló un host externo mediante una interfaz \textit{Loopback} en Router2 (que actúa como ISP), con la dirección pública \texttt{4.2.2.2}.

        \begin{lstlisting}
        Router2(config)# interface Loopback0
        Router2(config-if)# ip address 4.2.2.2 255.255.255.255
        \end{lstlisting}

        \begin{figure}[H]
        \centering
        \includegraphics[width=0.7\linewidth]{avion_router2_loopback.png}
        \label{fig:avion_router2_loopback}
        \end{figure}

        Para dar salida a Internet a Business y a Administración (Turista no debe tenerla), se configuró NAT con sobrecarga (\textit{overload}/PAT) sobre la interfaz pública del router. \textit{NAT} reescribe la IP de origen del paquete, cambiándola de la privada del PC a la IP pública del router antes de enviarlo, y realiza el proceso inverso al recibir la respuesta.

        \begin{lstlisting}
        Router1(config)# access-list 20 permit 10.10.20.0 0.0.0.255
        Router1(config)# access-list 20 permit 10.10.99.0 0.0.0.255
        Router1(config)# ip nat inside source list 20 interface GigabitEthernet0/1 overload
        Router1(config)# interface GigabitEthernet0/0.10
        Router1(config-subif)# ip nat inside
        Router1(config-subif)# interface GigabitEthernet0/0.20
        Router1(config-subif)# ip nat inside
        Router1(config-subif)# interface GigabitEthernet0/0.99
        Router1(config-subif)# ip nat inside
        Router1(config-subif)# interface GigabitEthernet0/1
        Router1(config-if)# ip nat outside
        Router1(config)# ip route 0.0.0.0 0.0.0.0 200.0.0.2
        \end{lstlisting}

        Cabe destacar que la red de Administración (\texttt{10.10.99.0/24}) también se agregó a la \texttt{access-list 20}, ya que la consigna exige que ese segmento tenga ``acceso total'', incluyendo Internet.

      \item
      \textbf{ACL: el hallazgo más importante del laboratorio} \\[0.5em]
        La consigna sugiere bloquear el acceso a Internet de Turista aplicando una ACL en sentido \textit{out} sobre la subinterfaz de esa VLAN, filtrando por dirección de origen \texttt{10.10.10.0/24}. Sin embargo, comprobamos que esa configuración, aplicada tal cual, \textbf{no bloquea nada real}: una ACL en sentido \textit{out} sobre una interfaz filtra el tráfico que está por \textit{salir} hacia esa red (es decir, tráfico \textbf{destinado} a Turista), mientras que la regla sugerida filtra por \textbf{origen}, condición que prácticamente nunca se cumple en ese sentido de tráfico. De hecho, durante nuestras pruebas el bloqueo de Turista hacia Internet se debía en realidad a la ausencia de una regla NAT para esa VLAN (el tráfico salía sin traducir y el router del ISP no podía devolver la respuesta), no a la ACL.

        La solución correcta consiste en aplicar la ACL sobre la interfaz de salida hacia el ISP, filtrando por origen en sentido saliente, que es la única ubicación donde efectivamente intercepta el tráfico de Turista antes de abandonar la red local:

        \begin{lstlisting}
        Router1(config)# access-list 100 deny ip 10.10.10.0 0.0.0.255 any
        Router1(config)# access-list 100 permit ip any any
        Router1(config)# interface GigabitEthernet0/1
        Router1(config-if)# ip access-group 100 out
        \end{lstlisting}

      \textbf{Conclusión} \\[0.5em]
        A nuestro criterio, la conclusión más importante de este punto es que, si se seguía la configuración sugerida en el enunciado al pie de la letra, la ACL no lograba bloquear nada real: al estar aplicada en sentido \textit{out} sobre la subinterfaz de Turista y filtrar por dirección de \textbf{origen}, nunca coincidía con el tráfico real saliente hacia esa red. El bloqueo observado durante nuestras primeras pruebas se debía, en realidad, a la ausencia de una regla NAT para la VLAN de Turista. La solución correcta fue trasladar la ACL a la interfaz de salida hacia el ISP, donde sí logramos bloquear específicamente el tráfico de Turista que intenta salir a Internet, de forma explícita e independiente de la configuración de NAT.
